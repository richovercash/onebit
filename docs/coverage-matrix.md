## CSCA circuit variants (enrollment)

The enrollment circuit verifies the CSCA→DSC signature; the CSCA key-type
distribution (588 CSCAs) drives the variants:

| CSCA key | Count | Enroll circuit | Status |
|----------|-------|----------------|--------|
| RSA ≤4096 (2048/3072/4096) | ~418 | `enroll` (RSA-4096, 35-limb, 19k gates) | ✅ live (US passport) |
| **brainpoolP256r1 ECDSA** | 160 | `enroll_ecdsa` (43k gates) | ✅ built + verifies (needs EU doc to test live) |
| RSA-6144 | 6 | `enroll_rsa6144` (52-limb, 23k gates) | ✅ built + verifies (real RSA-6144 cert) |
| P-384 ECDSA (secp384r1) | 4 | `enroll_p384` (SHA-384, 298k gates) | ✅ built + verifies (real P-384/SHA-384 cert) |

All four enroll variants cover **588/588** master-list CSCAs. Each verifies a
real synthetic cert of its type (compile + witness-solve in CI smoke) and
carries the F1 DSC-binding fix (negative-tested: tampering `dsc_modulus` fails
the constraint). Witnesses are regenerated by `Rsa6144Probe` / `P384Probe`
(gradle `:core:rsa6144Probe` / `:core:p384Probe`). P-384 CSCAs sign with SHA-384
(via `zkpassport/sha512`'s `sha384_var`) and use 48-byte coordinates; the
`enroll_p384` gate count is higher but enrollment is a one-time cost.
